# EFF Mod Manager

Windows application for installing EFF, managing local Mods, and repairing older Mod packages. This repository keeps its own source history; releases use verified, locally deployed artifacts from the EFF main checkout.

The unified EFF architecture, shared compiler package and user-selected index paths are documented in the [EFF main repository](https://github.com/ssice-a/EFF), especially [Shared Tools and Indexes](https://github.com/ssice-a/EFF/blob/main/docs/shared-tools-and-indexes.md).

Build and test with the .NET 9 Windows SDK from the EFF checkout. Manager links the pinned AnimeStudio core and index builder at build time and ships the resulting reader and decompression library; users do not need to install AnimeStudio or Blender. The EFF main repository's `tools/AnimeStudio` gitlink fixes this build-time dependency. A standalone Manager checkout without that source and the native validator is not a complete build environment.

- A manifest's author ID describes reusable content. Installing another copy creates a distinct directory and leaves earlier installations intact. Migration from backup does the same; migrating selected installed Format 2 Mods replaces each selected directory transactionally and keeps rollback copies.
- Create independent copy in the weapon editor duplicates the selected installation into its own directory, preserving the author's ID, resources, INI relationships and enable state. Each copy can select a different target weapon and keeps separate backups/runtime ownership. Changing one copy never retargets other copies with the same author ID. Importing the same package again also creates an independent installation.
- Editing a Mod name changes `[Mod] name` (and an existing `title`), independently of its directory, author ID and target weapon. Names need not be valid Windows folder names.
- Weapon Mods and weapon-mounted effect Mods expose one replacement-target selector per INI weapon binding, initialized to the saved target. Choices come from the validated local game index; names come from `WeaponBasicTable`, `ItemTable` and the game's CN/EN `I18nTextTable`, following the language in Settings. Bilingual weapon and character lists persist under `<resource-root>/.effmm-cache/catalogs/<installation>/`. Later starts read those small lists and check file metadata without opening the asset index or VFS blocks. Game/index changes, index workspace changes, or Reload list rebuild the weapon list. Full index loading is deferred until needed to build the initial list or apply a target; applying still validates the real game/index and parses only the selected native Prefab. Borrowed Mesh metadata uses a verified range from the existing incremental index sidecar.
- A weapon replacement covers every native Mesh in its model paths, including original VFX and all indexed LODs. Authored parts appear once per LOD; remaining original meshes receive skip rules. Shared game meshes are addressed through the selected Prefab's preload scope, so a common Quad is never globally replaced. Explicit weapon effect mounts update their real renderer paths and LOD anchors. Other weapons, replacement-effect Prefabs, author resources, controls and animation data are preserved. Ambiguous authored-to-target mappings are reported before changing the INI.
- The weapon destination list is grouped by weapon type (Sword, Greatsword, Polearm, Handcannon and Arts Unit), then sorted by localized name within each type.
- Character Mod details show the current character's localized game name and the INI's Mesh, Prefab and LOD target paths. Names come directly from `CharacterTable` and CN/EN `I18nTextTable`; viewing characters does not read the asset index or change the Mod. Borrowed material sources are not targets. Character selection is read only because skeleton, skinning, physics and animation bindings are character specific; there is no one-click character retargeting.
- Applying validates the complete candidate through the shipped Format 3 validator, checks for external INI changes, saves the original under `.effmm-backups`, then atomically replaces only the descriptor. Reload with F10 in the game; grip, scale and animation compatibility across weapon types still require in-game inspection.
- Format 3 checking uses the shared native manifest/control compiler shipped in `native/eff_author_assets_format3.dll`. It validates INI relationships, generic control expressions, Part visibility, and the existence and containment of declared files. It does not open payloads, build `compiled.bin`, download a compiler or require a game index. Native resource contents, legacy control resources, sampled animation data, physics/effect content and current game logical matches are validated by the demand-driven runtime; a successful declaration check is not full in-game acceptance.
- Missing authored files or invalid declarations are reported precisely and left unchanged. Manager cannot reconstruct missing geometry/pixels or guess a new logical target. Restore the missing resource or re-export it from the author project. Valid Format 3 packages require no offline cache repair.
- Index acquisition reuses a validated selected/registered workspace or a portable `.effindex.gz` already in the resource folder, its `indexes/` subfolder, or the download cache. Otherwise Manager downloads the package matching the installed game's Bundle content from the EFF releases. If automatic download fails, save the original package under `<resource-root>/indexes/` and reload the weapon list or retry the operation. Manager discovers and validates the file automatically. You can also choose it from any folder via **Repair > Import local index**. Maintainers publish new packages when the game content changes. [Download catalog](https://github.com/ssice-a/EFF/releases/latest/download/eff-index-catalog.json) · [EFF Releases](https://github.com/ssice-a/EFF/releases)
- Format 2 migration also needs the compatible migration toolset. Prepare it in Settings or install a complete verified shared-tools package before working offline.
- The Logs page retains the latest 400 events with original errors, technical details, actionable recovery steps, direct download/release links and local destinations. A missing index points to EFF releases and Repair > Import local index; it never asks users to rename a portable archive into an index. Tools can be installed offline by placing `eff-native-tools.json` and its matching `EFF_Shared_Native_Tools_*.zip` in `<resource-root>/tools/downloads/`, then clicking Prepare shared tools. The normal installer validates the manifest, size and SHA-256, extracts the archive and writes its receipt. Downloads are never accepted unchecked.
- Logs persist under `<resource-root>/.effmm-cache/logs/` (or `logs/` beside Manager before a resource root is selected). Disk history rotates at 2 MiB with one previous file; inability to write a log remains visible in the page while session events can still be copied. Changing UI language also changes the displayed error explanations and recovery steps.

From the EFF root, build the native validator before building Manager:

```powershell
cmd /d /c tools\diagnostics\build_author_assets.cmd format3
dotnet run --project EFF-Mod-Manager/tests/EFF.ModManager.Tests/EFF.ModManager.Tests.csproj -c Release
dotnet run --project EFF-Mod-Manager/tests/EFF.ModManager.IntegrationTests/EFF.ModManager.IntegrationTests.csproj -c Release
```

The integration suite calls the actual Repair service, parses a small real UnityFS/SerializedFile fixture through the local VFS reader, exercises offline and manual index acquisition, and checks that linked core dependency versions stay in sync. Local installation remains the responsibility of `tools/release/build_deploy_local.ps1 -Component Manager` in the EFF main repository.

Release packages must come from the locally built, tested and deployed Manager directory (`E:\EFF-Mod-Manager`) under the EFF main repository's `docs/release-management.md` procedure. Include the complete publish output: the Manager executable, `native/eff_author_assets_format3.dll`, `AnimeStudio.Ooz.dll`, `CNKeys.json`, native texture libraries and notices/licenses. Do not copy only the executable. The manual GitHub workflow intentionally reports this policy instead of rebuilding source or creating a different release artifact in the cloud.
